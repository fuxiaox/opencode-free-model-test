2. 测试方法

2.1 总体思路

以 opencode run 作为统一调用入口（非交互模式，与 TUI 走同一套 provider 链路），对每个模型施加完全相同的题目，记录各维度指标：

维度观测指标
连通稳定性连续 N 轮中完全通过的轮数（pass rate）
响应延迟每轮端到端耗时：平均 / 中位 / 最小 / 最大
工具调用是否真正调用 read 工具读出夹具文件中的密钥
推理能力注水池多步算术题是否得出正确答案
代码生成是否给出可用的函数实现；是否满足复杂度要求

2.2 测试题目

题目 A —— 标准题（工具调用 + 推理 + 代码，三合一）

Read MODEL_TEST_FIXTURE.md and report the value after SECRET_CODE:.
Answer: two pipes fill a pool, A takes 6 hours, B takes 4 hours, both together how many hours?
Write a one-line JS function isPrime(n).
Output three lines: SECRET=<value>, HOURS=<number>, CODE=<fn>

配套夹具文件 MODEL_TEST_FIXTURE.md（同目录），内含唯一标记：

SECRET_CODE: ZX-9137-QQ

三项判定（pass = 三项全中）：

字段判定正则考察点
secret输出含 ZX-9137-QQ工具调用：必须真的用 read 打开文件才能拿到值，无法靠猜
hoursHOURS[:=] 2.4（或 12/5）多步推理：1/6 + 1/4 = 5/12 → 12/5 = 2.4 小时
code输出含 isPrime代码生成

题目 B —— 质量题（算法题）

Write a JavaScript function longestIncreasingSubsequence(arr) returning the length of
the longest strictly increasing subsequence, O(n log n).
Then answer: what does longestIncreasingSubsequence([10,9,2,5,3,7,101,18]) return?
Output exactly two lines: ANSWER=<number> and CODE=<the function>
  • 标准答案 ANSWER=4（例如 2,3,7,18）
  • codeOk：代码含 function 或 =>，且含 bisect|lower_bound|tails|push|splice|sort 之一
  • 正则未命中时一律人工复核实际代码（本次对 space-bunny / nemotron / glm 三例做了人工复核，均为正确实现，判定为正则误报）

2.3 稳定性测试协议

  • 每个模型连续执行 N 轮同一道题（N = 5 为主，部分模型 N = 3）
  • 记录逐轮耗时数组，统计 pass 数、平均值、中位数、最小值、最大值
  • 中位数优先于平均值：免费档存在偶发长尾，均值容易被单次冷启动 / 排队拉偏
  • 首轮存在冷启动（实测首次调用可达 85s+），故以中位数与多次采样为准

2.6 方法局限性

  1. 单时段快照：免费档延迟随平台负载剧烈波动，跨时段差异可达数倍，结论仅代表采样时刻。
  2. 样本量有限：每模型 3~5 轮，只能发现明显的稳定性问题，无法刻画长尾概率。
  3. 题目偏简单：标准题所有可用模型均满分，未能拉开差距；区分度主要来自延迟与稳定性。
  4. 判定用正则启发式：代码质量未做人工逐行评审，可能漏判风格问题或同解不同写法。
  5. 未覆盖：超长上下文、视觉输入、工具并发、流式中断恢复、token 配额约束。

4. 不可用模型及原因

A. opencode-zen 提供商 —— 全部 7 个模型，API key 已过期

模型状态
opencode-zen/big-pickle❌ API key 过期
opencode-zen/deepseek-v4-flash-free❌ API key 过期
opencode-zen/ling-3.0-flash-fin-free❌ API key 过期
opencode-zen/mimo-v2.5-free❌ API key 过期
opencode-zen/muse-spark-1.3-contributor-free❌ API key 过期
opencode-zen/nemotron-3-ultra-free❌ API key 过期
opencode-zen/nemotron-3.5-lightning-free❌ API key 过期

报错原文：

Error: This API key has expired. Create a new API key in OpenCode Console and replace it in your client or secret store. Signing in again will not renew this key.

排查结论：opencode-zen 是配置在 ~/.config/opencode/opencode.jsonc 里的手动自定义 provider，指向遗留端点 https://opencode.ai/zen/v1 + 一个硬编码的过期 key，与内置 opencode 通道完全独立。

实测尝试过用 Console OAuth（浏览器 "Authorize OpenCode CLI"）重新连接，未能产出可填入的 sk- key：OAuth 授权与 sk- API key 属两套体系，opencode auth export 中仍只有 Zhipu 账号。要使用这 5 个 zen 专属模型（mimo-v2.5-free、nemotron-3.5-lightning-free、nemotron-3-ultra-free、muse-spark-1.3-contributor-free、ling-3.0-flash-fin-free），需在 opencode.ai/console → API keys → Create key 生成真实 sk- key。

这些模型与已可用的 7 个高度重叠（mimo-v2.6 > mimo-v2.5、nemotron-3.5-super-vl 已覆盖 nemotron 系列），实际增益有限。

B. beam-free —— 地区限制

Error: This model is not available in your country

官方文档列明该模型在部分国家 / 地区不可用，当前网络环境位于受限范围。

C. space-bunny-free —— 已从模型目录移除

客户端直接返回 Model unavailable（<1s 拒绝，非超时），属目录层面移除而非服务故障。
